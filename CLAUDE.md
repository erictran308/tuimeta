# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

tuimeta: a terminal client for personal Facebook Messenger, Instagram and WhatsApp accounts, with vim-style modes. It's tuigram (`../telegram-rust`, a Telegram client on TDLib) ported to Meta's messengers: the UI, keys and security rules are tuigram's, minus what Meta's messengers don't have. Two programs: `tuimeta`, the app (Rust, ratatui, tokio, MIT), and `tuimeta-helper` in `helper/` (Go, AGPL-3.0-or-later), which speaks Meta's protocols through mautrix-meta's `messagix` (Messenger, with `whatsmeow` for its encrypted chats), `instameow` (Instagram) and `whatsmeow` (WhatsApp, as a linked device). The app starts the helper as a child process and talks newline-delimited JSON over its stdin/stdout; `helper/PROTOCOL.md` is the contract, and changes to it go in that file first.

Using an unofficial client is against Meta's terms and can get an account locked or banned; the README says so up front, and the login screen too.

## Never run the app against a real account

The data directory holds the user's logged-in sessions: the platform app-data dir (`tuimeta --help` prints it), or `TM_DATA_DIR`. Running the binary connects as them, reads their chats and sends read receipts to real people, and logging in from a new place is what trips Meta's checkpoints. Don't `cargo run` to check a change: verify with tests that render into ratatui's `TestBackend`, `tuimeta --demo` (no helper at all), or `tuimeta --fake` (the helper's made-up accounts, no network, its own `helper-fake` folder). Never log into Messenger or Instagram, or link WhatsApp, from a test or a script; the helper's tests use `--fake`, recorded data and hand-built whatsmeow events only, and their WhatsApp connection is a fake (`fakeWA`) that never connects.

## Commands

```sh
cargo build
cargo test                       # the app's tests
cargo clippy --all-targets       # keep it warning-free
cargo fmt
(cd helper && go build -o ../target/debug/tuimeta-helper .)   # where a debug build finds it
(cd helper && go test ./... && go vet ./... && gofmt -l .)
cargo run -- --fake              # the whole app against the fake helper
```

`meta::helper_path` finds the helper next to the `tuimeta` binary, or in development builds where `TM_HELPER` (environment or `.env`) says, which must be an absolute path (`meta::dev_helper`). `.env` is read only by development builds, only from the repository they were built from (`CARGO_MANIFEST_DIR`) and only `TM_*` keys, into a map `config::var` falls back to (never the process environment). `TM_DATA_DIR` must be on this machine. On Unix every folder above it must be changeable only by the user or root (group write counts as others unless the group is the user's own, `config::private_group`; root-owned sticky folders are fine), every link on the way the user's or root's (`links_are_yours`), and the folder the user's; the path checked, links resolved, is the one used (`config::private_place`), and after the chmod it must really be the user's and 0700, not on a macOS volume that ignores ownership (`config::kept_private`). On Windows it must be inside `%USERPROFILE%`, by name and once junctions are followed. The data dir is set to 0700 on every start. The helper gets `<data dir>/helper` (or `helper-fake`) and keeps everything it writes there, 0600.

The published crate never includes `helper/` (`exclude` in `Cargo.toml`): it's AGPL, the app MIT. Keep them separate programs that only share the documented protocol.

## Security

Everything another user sends is untrusted: text, names, chat titles, file names, links, files, images, and the network's own service sentences (which embed names).
- Text that is shown or copied goes through `text::clean` (control characters other than `\n`/`\t`, bidi overrides and marks, invisible characters terminals and the layout disagree on, format characters that do nothing in a chat, variation selectors past the sixteenth and unassigned invisible code points; joiners, variation selectors and tags stay only where they join something, `text::Keep`), and so do the helper's error sentences. `Msg` text is cleaned in `messages::normalize`, which keeps link and formatting ranges in step. One-line snippets, chat titles and chat previews keep at most 300 characters; a snippet or title cut short ends with `…` (`messages::one_line`, `chats::one_line`), so padding can't pass for its end. Entity offsets from the helper are UTF-16 code units, mapped once per message (`messages::Utf16Offsets`), and at most `MAX_ENTITIES` are taken, so a message converts in time in step with its size; byte slicing uses `.get()` or ranges known to be on char boundaries.
- Links and files open through `open_externally` (the `open` crate, ShellExecute on Windows), never a shell. Only http(s) links are kept (`messages::web_url`, which writes a `\` before the query as the `/` browsers read it as, so every opener goes to the host shown). Downloaded files get the OS "from the internet" mark (`mark_downloaded`), and only `SAFE_TO_OPEN` types open without a `Confirm`; so do links whose text differs from their URL (`Link.disguise`, kept when the same URL also appears plainly; text is the same place only if the path's case and any scheme it names match, `messages::same_place`), and links with an `@` in their authority or a host with non-Latin letters or an `xn--` label (`app::look_alike`). A link's `Confirm` shows its host on its own line, cut from the left (`link_host`), flagged when it has other scripts' letters (`other_scripts`). A `Confirm` ignores `y` for `CONFIRM_GRACE` from when it's first in view, on the chats screen with the terminal focused (`App::confirm_in_view`); it's dropped when the login screen takes over, and a `Logout` one when its network is logged out of. A download finishing while a popup, prompt or the composer is in use waits for Enter (`App::busy`). Enter doesn't open a message that came in, changed or came under the cursor through a deletion within `CONFIRM_GRACE` (`App.changed`, `App::just_changed`): it asks for a second Enter. A link preview (`Msg.card`) shows only if it's of one of the message's own links, named by the host in its URL, cut from the left (`truncate_start`); a link too long for the open menu shows its real host, then its path (`ui::messages::link_label`).
- Read receipts go out only from `App::mark_seen` (`Meta::mark_read`), when the chat pane and the terminal window have focus and the view is on the newest message (`App::watching`). Where the terminal never reports focus, a key within `IDLE_AFTER` stands in for it; where it does, a key within `AWAY_AFTER`. Idle time is the longer of the monotonic and the wall clock (`App::idle`). While a jump to an older message loads (`Page::Around`), nothing is watched; nor under a popup, the emoji suggestion list included (`App::popup_over_chat`). A message request (`Chat.request`) gets none until it's accepted (answering accepts it). A message deleted under the cursor moves it to its neighbour, never back to following the newest (`OpenChat::remove`), so no receipt goes out without a key press. Don't call `mark_read` anywhere else.
- Typing goes out only from `App::set_typing` (`Meta::send_typing`): while the composer has text after an edit (again every `TYPING_EVERY`), and a stop when it's emptied, Insert mode is left or the chat changes. There is no presence ("active now") at all: the helper must never send it (PROTOCOL.md, "What the helper must never do").
- Files go out only from `OpenChat.attachments`, listed by name and size in the composer (a link to a file in another folder by that file's path, from `~`), on Enter, and not if one was swapped since it was listed (`Attachment::swapped`: device, inode, size, modification and status-change times). `send_files` names each file with that identity (`Attachment::to_send`, `meta::FileToSend`), and the helper opens it without following a link and sends nothing unless every open file is that one and gives exactly its size (`server.readUpload`). A paste attaches only absolute paths of existing files; `\\server\share` paths are never looked at, by a paste, the `a` prompt or its Tab completion (`attach::on_another_machine`). The clipboard is read only on `p` / Ctrl-v, and a paste that comes back after the chat changed (`Pasted.chat_id`) or once the keys went to the chat list is dropped.
- Login is by pasted cookies (`LoginStep::Cookies`) for Messenger and Instagram: the input is masked, the app checks the required names are there (`Network::cookie_names`) and hands the text to the helper, which keeps it only in its data folder. WhatsApp links a device instead (`LoginStep::Link`, `Network::links`): a QR code drawn from the helper's `login_code` (`ui::qr_lines`, black on white, at most `MAX_QR` bytes, never shown as text), or for the account's number (typed in the open) a pairing code, shown only if it looks like one (`app::pairing_code`); `login_link`, `cancel_login` and `login_code` carry the attempt (`App.login_attempt`), so Esc and `p` always cancel the current attempt's link and no other (Esc on the number step needn't: the `p` that opened it did), an `error` event doesn't end a link's wait (only its `LoggedIn` or `Gone` does), and answers or codes of a login given up are dropped; once the phone confirms a link it completes, and whatsmeow's `PrePairCallback` refuses one cancelled before that. Neither codes nor numbers are logged. Passwords are never asked for. The login screen says tuimeta isn't Meta's and what that risks (`ui::NOT_META`).
- Media seen only once (Instagram's and WhatsApp's view-once, `Media.view_once`) has no file and no preview: the bubble names it and says to open it on the phone (`messages::ON_PHONE`). It's never downloaded or handed to another app.
- WhatsApp (`helper/internal/whatsapp`): a name someone gave themselves shows as `~Name`, and a stranger's DM title adds their number, whole however long the name (`refreshName`, `title`); status updates and channels aren't chats (`skipped`), only phone-number and `@lid` JIDs become the people a message names (mentions, quotes, events, a deletion's owner: `personJID`), and a chat that isn't a person's or a group's (a bot's) is read-only: no message, reaction, edit, deletion, mute, typing or read receipt goes to it (`sendable`, `errCantSend`); a group's timer comes only from WhatsApp itself (`GroupInfo`, `groupDetails`, or the phone's sync at linking), a chat's only as one of WhatsApp's values (`timerAllowed`), and an older setting never undoes a newer one (`EphemeralAt`); a message id sent again never replaces a message (only a `Placeholder`'s decryption does), nor within one history sync (`inSync`), and a deleted message leaves a tombstone so no later copy brings it back (`deleted.go`, `wasDeleted`, `tuimeta_deleted`); edits come only from the sender, never of events, within `EditWindow` plus `editSlack`, and the phone's history follows the live rules for edits and deletions (`edit`, `historyRevoke`; an edit of a message not here yet waits, `holdEdit`); a quote is linked to a kept message only if the reply names its sender, and shows it as kept; read receipts go to everyone only when the account's read-receipt setting, asked once each connection, says so, else only to the user's own devices, and none when it can't be fetched (`waConn.MarkRead`, `receiptKind`); sender-controlled sizes are capped (`MaxText`, `MaxThumb`, `MaxField`, `MaxMentions`, `reactionLike`, history reactions included, `downloadLimit`, `proto.Media` clamps numbers), and a file is downloadable only with a 32-byte hash and media key (`fullRef`); a message's downloads go when it does, unless another message still shows the same file (`forgetFiles`, `stillShown`). The shared formatting parser (`metatext`) must stay linear in the text and its mentions (n log n at worst for code fences, `codeScan`; a mention's range stops at the text's end): `speed_test.go` checks hostile shapes (long backtick runs, tens of thousands of mentions) and compares it with mautrix-meta's rules.
- Messenger and Instagram are held to bounds too: an encrypted Messenger attachment downloads into a file capped by its kind (`waLimit`: `MaxPhoto`, `MaxSticker`, else `download.MaxSize`) and isn't asked for if its message states more; a link over `MaxLink` is dropped and Facebook's redirect unwrapped at most twice (`webLink`), Instagram's shims at most `maxUnwrap` deep; Messenger's lookups of unknown people go `ContactsAtOnce` at a time, at most `MaxContactLookups` per `ContactWindow` and `MaxContactQueue` waiting; a Messenger message names at most `MaxMentions` people, each once (`mentionSet`), and an Instagram message keeps at most `maxMentions` mentions, picked before anyone gets an id; Messenger's and Instagram's `MarkRead` send nothing for a message request. Messenger's encrypted events count only from a person's (`msgr`, `s.whatsapp.net`) or a group's (`g.us`) JID, a DM's only from its person (`waChatKey`, `waChat`); an encrypted message id sent again never replaces a message (only a `placeholder`'s decryption does); a read-self receipt counts only from the user's own devices, and a receipt's ids are found through `c.waIDs`; encrypted reactions must pass `reactionLike`; a file is keyed by sha256 of its hash and media key together, as WhatsApp's are; a quote of a message not kept names nobody.
- Encrypted chats (`Chat.encrypted`: every WhatsApp chat, Messenger's encrypted ones) show a 🔒 on `colors.secret` (`ui::lock_spans`), which a name starting with 🔒 can't imitate, and their composer's border says "end-to-end encrypted". Their notifications say only "Encrypted chat: New message".
- Service messages (`service.rs`) are the network's sentence, cleaned onto one line and drawn in the text color, never muted like a date, so a name can't pass for one; they keep no link or formatting ranges.
- Only PNG, JPEG, GIF and WebP images are decoded (`images::picture_format`), within `images::limits` (stickers within 1024 px), at most `MAX_BUILDING` at once and `MAX_RUNNING` decoder threads, counting ones given up on after `BUILD_TIMEOUT`, and a panic in a decoder only marks that image broken (`images::panic_is_contained`). Sixel and iTerm2 images aren't drawn under popups (`Images::paints_over`), and with them the terminal is cleared whenever the login screen, a popup over the chat or the viewer's photo (or its zoom) changes (`app::must_clear`, `Layers`), so no picture shows through a warning's blank cells.
- Notification text goes through `notify::escape`, which turns `<`, `>` and `&` into look-alikes (`notify::field`), so no notifier reads markup in it. A panic restores the terminal and exits, printing the message through `text::clean`; the helper then sees its stdin close and stops without telling anyone anything.
- Settings are written 0600 through a rename (`Settings::save`); `clean_outbox` deletes only `pasted-<digits>.png/jpg`, and the outbox must be a folder of the user's, not a link, and is set to 0700 whenever an image is saved there (`clipboard::private_folder`); `--demo` writes only into a new 0700 temp folder.

## Architecture

**Event loop (`app.rs`, `App::run`).** One `tokio::select!` over: the helper's events, finished image encodes, clipboard results, terminal key/paste/focus events, signals and the quit deadline. Each wake drains the event backlog, then redraws. All state lives in `App`; nothing else mutates it.

**Helper connection (`meta.rs`).** `Meta::start` spawns the helper, checks its `hello` line (protocol `PROTOCOL_VERSION`) and runs a reader and a writer task. Every request is fire-and-forget (`Meta::spawn`, or `Meta::then` to turn the answer into an event); answers and the helper's own events come back as `MetaEvent`s. Requests carry what was asked (chat id, `Page`, query) so stale answers can be dropped. The helper assigns every id: chat and user ids are unique across networks, message ids are chronological (`ms << 8 | slot`), so `OpenChat.messages` (a `BTreeMap`) stays in order, and a message with several photos arrives as consecutive "album" parts. `Meta::detached` (demo, tests) sends nothing and, in tests, records every request (`Meta::sent`) so tests can check what would have gone out. A line over `MAX_LINE` (16 MiB, twice what the helper writes) is skipped to its end without being held, and fails only the request whose `id` it starts with (`meta::read_line`, `answer_id`). `MetaEvent::Gone` means the helper stopped: the status bar says so; a helper that broke the protocol is killed first, so it shows at once.

**Accounts and login.** `App.accounts` holds each network's `AccountState` from the helper's `account` events. `App::follow_accounts` shows the login screen while no account is ready, and the chats once one is. `LoginStep::Choose` picks a network, `LoginStep::Cookies` takes the paste, `LoginStep::Link` (`Linking::Qr`, `Phone`, `Pairing`) shows WhatsApp's codes (`Meta::login_link`/`cancel_login`, `MetaEvent::LoginCode`; `p` cancels the codes shown and switches to the phone number, Enter asks for a fresh code after one ran out); `:login` opens it over the chats (`Login.from_main`, so Esc goes back). `TM_BROWSER` ("Chrome 150.0.7712.45", read once into `App.browser`) goes with each login as `login_cookies`' `browser`: the helper (`internal/browser`) then says it's that Chrome on this computer's system instead of the libraries' Chrome 141 on Linux, saved with the session so a session never changes browser; only Chrome can be named, since the libraries' TLS handshake is Chrome's. A network logged out of (`:logout`, which asks and names it — for WhatsApp it says tuimeta unlinks itself — or the session ending elsewhere) has its chats, jumps and highlights forgotten (`App::forget_network`), and every network's pictures and downloaded-file paths with them (`Images::forget`: files aren't told apart by network, so the others' are asked for again).

**Chat list (`chats.rs`, `ui/chat_list.rs`).** Rebuilt from the helper's `chat` events (`Chats::upsert`, which keeps what only the app knows: who is typing, a downloaded photo). Order is unread first, then `order` (last activity in ms); a new message moves its chat at once (`Chats::on_message`). Tabs (`Chats::tabs`) are All, each network once there are two, and the archive once it has chats; Tab / Shift-Tab go round them. Chats load a page at a time per network, more as the cursor nears the end (`App::load_more_chats`), never all at once. `m` mutes on the network. Typing (`Chat.activity`) comes from `typing` events; the helper sends the stop itself.

**Open chat (`messages.rs`, `ui/messages.rs`).** As in tuigram: one unbroken stretch of history, `Page` (`Latest`/`Older`/`Newer`/`Around`) with `loading` the one request in flight, `selected: None` following the newest, `MAX_FOLLOWED`, `ScrollAnchor`. Messages are converted once (`Msg::from(&meta::Message)`): text with the media's label, links (the network's link entities and written-out addresses, `messages::links`), formatting (`styles`), the preview and file, the link card, the reply (`ReplyTo`, with the network's quote when it gives one, else fetched with `get_message`), reactions. A `message` event replaces a loaded message whole (`OpenChat::upsert`) or adds a new one: at the newest, or, one that arrives late, at its place inside the loaded stretch. A deletion (`App::on_deleted`, `OpenChat::remove`) moves a cursor on a deleted message to its neighbour, takes its quote out of replies, and ends what was about it: pending opens and copies of its files, its open/copy menu (`App.menu_message`), its `d` and `R` popups and an edit of it. Sending shows the message pending at once (the helper's `message` event) and `message_sent` swaps it for the final id (`OpenChat::replace`). `e` edits only your text messages while `editable_until` allows; text with formatting asks first (`Confirmed::Edit`). `d` unsends your own message (`DeleteMenu`). Albums are drawn as one bubble (`ui::messages::albums`); their reactions and reply are on the first part, their text on the last.

**Reactions (`reactions.rs`).** One per person per message. `R` opens `ReactMenu` with `reactions::OFFERED` (Messenger's six and other common ones), your reaction first; `/` searches every emoji in the `emojis` crate, without joined ones. Enter makes the emoji yours, or takes it back if it is (`reactions::same` ignores U+FE0F); `X` takes yours back.

**Finding chats (`picker.rs`).** `s` lists your chats matching what's typed, then whom each ready network's `search` found once typing pauses (`SEARCH_AFTER`). Picking a person starts `open_dm`, answered by `MetaEvent::ChatFound` and kept only if its network and user id match `App.finding` (two people can share a name) and nothing holds the keys.

**Notifications (`notify.rs`, `App::notify`).** Someone else's new message (`message.id` past the chat's `read_inbox` and the last one notified, `App.notified`), in a chat that isn't muted, from after the account came in (`notify_since`), that the user doesn't see (`App::sees`). `Notifier` batches them (`GAP`, `QUIET_CHAT`) and drops ones read elsewhere (`remove_read`) or deleted. The window title counts unread unmuted chats.

**The helper (`helper/`).** Go, pure (`CGO_ENABLED=0` builds for all six targets). `internal/server` reads requests and writes events (one writer, so lines never interleave, and none longer than `MaxOutLine`, 8 MiB: a `history` page is cut to `PageBudget`, `fitPage`); it runs a network's `load_chats` one at a time (`Server.loading`) and a chat's `typing` in the order requested (`call.seq`), and `send_files` reads only the file tuimeta listed (`readUpload`). `internal/backend` is the `Backend` interface each network implements, with `Deps` (`internal/ids`: chat and person ids persisted in `ids.json`, message ids for the run, album splitting; `internal/session`; `internal/download`, whose `Remove` forgets a deleted message's file id and stops its download, and whose `Forget` forgets a logged-out network's; the `Outbox` of messages being sent). `internal/fake` is the `--fake` world. `internal/messenger` drives mautrix-meta's messagix (facebook.com mode, cookie login, the session saved only after the first sync) and, for encrypted chats, whatsmeow as a registered device of the account, whose store and the encrypted messages it received (newest 3000 per chat; older encrypted history is only in Messenger's PIN-locked backup, which neither library can restore, so there's no PIN prompt) are in `messenger/e2ee.db` (modernc SQLite, 0600, opened through `fsutil.OpenPrivate`, not encrypted at rest yet), with how far each encrypted chat was read (`tuimeta_e2ee_read`, saved by `readElsewhere`, read back in `openStore`): Messenger's thread rows never learn of encrypted receipts, so their watermark and unread count stay stale. A task guard lets read receipts out only from `mark_read` and typing only from `typing`; the whatsmeow wrapper (`e2eeAPI`) has no presence methods at all, and its `MarkRead`, `MarkReadSelf` and `SendChatPresence` take the request's purpose and refuse any but `mark_read`/`typing`, as `waAPI`'s do. `MarkRead` sends nothing for an encrypted group's changes, and where Messenger says the user's read receipts are off in a chat (`receiptsOff`) its encrypted receipts are read-self (`markReadWA`). Encrypted edits and reactions are kept only when they changed a kept message and don't count toward `MaxStoredPerChat`; a chat that leaves the list has its rows forgotten (`forgetKept`); nothing that could fetch view-once media is kept, and a quote's copy only as text (`keptApplication`); disappearing messages go when their sender's timer says, with their downloads (`expire`, at start and every `SweepEvery`), and what's sent carries the chat's timer (`sendMeta`); an encrypted unsend takes the message's downloads too. A message row that can't be applied is logged and dropped alone (`applyRow`), and a reply's quote reads only the first `maxQuoted` bytes of what it quotes. Messenger's `logout` is local only: it disconnects and wipes what's stored (the encrypted-chat device store included) but never calls facebook.com's log-out, so the browser the cookies came from stays logged in. `internal/instagram` drives instameow (Instagram's protocol since July 2026; no encryption since May 2026): each file goes as its own message, a caption as a text after it, a shared post's link is added to the text so its card shows, and `logout` can't end the session on Instagram's side. `internal/whatsapp` drives whatsmeow as a linked device (`login_link`, `backend.Linker`; QR or pairing code; named "Chrome (<OS>)" on the phone, `describeDevice`): WhatsApp keeps no history on its servers, so the chats and messages this device has are in `whatsapp/wa.db` (modernc SQLite, 0600, opened through `fsutil.OpenPrivate`, rows as JSON, newest 3000 per chat, read back lazily per chat, with deleted messages' tombstones in `tuimeta_deleted`, at most `MaxDeletedPerChat`), and older ones are asked of the phone (`HISTORY_SYNC_ON_DEMAND`, not again for `PhoneQuietFor` after it didn't answer). People and DMs are keyed by WhatsApp id (`…@lid`) once known, else by number; when the pairing is learned, `ids.Store.RenameChat`/`RenameUser` keep tuimeta's ids (`WhatsApp::learn`, `resolve`). View-once media keep nothing that could fetch them; disappearing messages are deleted when their time is up, with their downloads, read from the row when not loaded (`sweep`, `deleted`), also while tuimeta was closed, and an unlinked device's store stays open to go on sweeping until logout or a new link (`sweepKept`); deletions and app-state changes on the phone follow. `waAPI` has no presence methods, and its `MarkRead`/`SendChatPresence` take the request's purpose and refuse any but `mark_read`/`typing`; the only app state sent is mute. WhatsApp's `logout` unlinks the device (tuimeta's own, not shared with a browser) and wipes `whatsapp/`. `internal/metatext` turns every network's inline markers (`*bold*` `_italic_` `~strike~` `` `code` ``) into entities. Every library logger writes nothing; `hlog` keeps only fixed words, numbers and error kinds, in a `helper.log` opened only as a plain file of the user's, never through a link (`fsutil.OpenPrivate`). Downloads only go over https to Meta's CDN hosts (WhatsApp's attachments through whatsmeow, its profile pictures from `whatsapp.net`). What each network still needs to send to work (socket pings, frame and delivery acks) is listed in `helper/README.md` → Privacy; keep that list true when changing a backend. The tests never touch a real account: they use hand-built library structs and recorded-looking JSON. The app has been tried live only on the author's own accounts: Messenger and Instagram log in, Messenger's encrypted chats connect, and WhatsApp links as a device, connects and keeps its chats across restarts. WhatsApp has been used only briefly, so treat the rest of its live behavior as lightly tested.

**The rest** works as in tuigram: modes and keys (`on_key` routes to the first modal layer: confirm, photo viewer, settings, delete, react, open/copy menu, picker, resize, prompt, Insert, Normal; update the status bar hints and `ui/help.rs` `SHORTCUTS` when adding keys), `:` commands only by their full name with Tab completion (`login`, `logout`), images (`images.rs`), the photo viewer (`viewer.rs`, `ui/viewer.rs`: `h` / `l` go through the loaded photos, loading more past them, `j` / `k` zoom through `viewer::SIZES`, never past filling the window; while it's up nothing is marked read or held back from notifying, the cursor stays on the photo, pastes are dropped, and Ctrl/Alt keys do nothing; at most `MAX_LARGE` window-sized encodes are kept), clipboard (`clipboard.rs`), attachments (`attach.rs`), themes (`theme.rs`), corners and pills (boxes come from `ui::bordered`, never `Block::bordered`, round where the font has `╭`: `Colors.rounded`, set each frame from `Settings.corners`, `theme::Corners::Auto` square on the Linux console, hardware terminals and the old Windows console; bubbles stay square; labels on a background of their own go through `ui::pill`, which with `Settings.nerd_font` turns their end spaces into Powerline half circles, so nothing moves), the demo (`demo.rs`: scenes `1`–`9`, never calls `App::run`), and the terminal (`term.rs`: ratatui's crossterm backend, but the blank ratatui sends behind an emoji with U+FE0F, like ❤️, goes before it, `blank_first`; sent after it without a cursor move, terminals that draw the emoji two columns wide shifted the rest of the row one column right).

## Conventions

- Rust 2024 edition; `let` chains are used freely.
- Comments explain why, in plain sentences; doc comments describe behavior as the user sees it.
- Test names are sentences. UI tests render into a `TestBackend` buffer and assert on rows/cells; app tests use `crate::demo::demo_app` with `Meta::detached` and check `Meta::sent`.
- The helper's Go code follows the same: plain comments on why, tests for everything, `--fake` kept complete enough to drive the whole UI.
