# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

tuimeta: a terminal client for personal Facebook Messenger and Instagram accounts, with vim-style modes. It's tuigram (`../telegram-rust`, a Telegram client on TDLib) ported to Meta's messengers: the UI, keys and security rules are tuigram's, minus what Messenger and Instagram don't have. Two programs: `tuimeta`, the app (Rust, ratatui, tokio, MIT), and `tuimeta-helper` in `helper/` (Go, AGPL-3.0-or-later), which speaks Meta's protocols through mautrix-meta's `messagix` (Messenger, with `whatsmeow` for its encrypted chats) and `instameow` (Instagram). The app starts the helper as a child process and talks newline-delimited JSON over its stdin/stdout; `helper/PROTOCOL.md` is the contract, and changes to it go in that file first.

Using an unofficial client is against Meta's terms and can get an account locked or banned; the README says so up front, and the login screen too.

## Never run the app against a real account

The data directory holds the user's logged-in sessions: the platform app-data dir (`tuimeta --help` prints it), or `TM_DATA_DIR`. Running the binary connects as them, reads their chats and sends read receipts to real people, and logging in from a new place is what trips Meta's checkpoints. Don't `cargo run` to check a change: verify with tests that render into ratatui's `TestBackend`, `tuimeta --demo` (no helper at all), or `tuimeta --fake` (the helper's made-up accounts, no network, its own `helper-fake` folder). Never log into Messenger or Instagram from a test or a script; the helper's tests use `--fake` and recorded data only.

## Commands

```sh
cargo build
cargo test                       # the app's tests
cargo clippy --all-targets       # keep it warning-free
cargo fmt
(cd helper && go build -o ../target/debug/tuimeta-helper .)   # where a debug build finds it
(cd helper && go test ./... && go vet ./... && gofmt -l .)
cargo run -- --fake              # the whole app against the fake helper
```

`meta::helper_path` finds the helper next to the `tuimeta` binary, or in development builds where `TM_HELPER` (environment or `.env`) says. `.env` is read only by development builds, only from the working directory and only `TM_*` keys, into a map `config::var` falls back to (never the process environment). `TM_DATA_DIR` must be on this machine, and on Unix have only private or root-owned sticky folders above it (`config::private_place`); the data dir is set to 0700 on every start. The helper gets `<data dir>/helper` (or `helper-fake`) and keeps everything it writes there, 0600.

The published crate never includes `helper/` (`exclude` in `Cargo.toml`): it's AGPL, the app MIT. Keep them separate programs that only share the documented protocol.

## Security

Everything another user sends is untrusted: text, names, chat titles, file names, links, files, images, and the network's own service sentences (which embed names).
- Text that is shown or copied goes through `text::clean` (control characters other than `\n`/`\t`, bidi overrides and marks, and invisible characters terminals and the layout disagree on). `Msg` text is cleaned in `messages::normalize`, which keeps link and formatting ranges in step. One-line snippets and chat previews keep at most 300 characters. Entity offsets from the helper are UTF-16 code units (`messages::byte_offset`); byte slicing uses `.get()` or ranges known to be on char boundaries.
- Links and files open through `open_externally` (the `open` crate, ShellExecute on Windows), never a shell. Only http(s) links are kept (`messages::web_url`). Downloaded files get the OS "from the internet" mark (`mark_downloaded`), and only `SAFE_TO_OPEN` types open without a `Confirm`; so do links whose text differs from their URL (`Link.disguise`, kept when the same URL also appears plainly). A link's `Confirm` shows its host on its own line, cut from the left (`link_host`). A `Confirm` ignores `y` for `CONFIRM_GRACE`, and a download finishing while a popup, prompt or the composer is in use waits for Enter (`App::busy`). A link preview (`Msg.card`) shows only if it's of one of the message's own links, named by the host in its URL.
- Read receipts go out only from `App::mark_seen` (`Meta::mark_read`), when the chat pane and the terminal window have focus and the view is on the newest message (`App::watching`). Where the terminal never reports focus, a key within `IDLE_AFTER` stands in for it; where it does, a key within `AWAY_AFTER`. Idle time is the longer of the monotonic and the wall clock (`App::idle`). While a jump to an older message loads (`Page::Around`), nothing is watched. Don't call `mark_read` anywhere else.
- Typing goes out only from `App::set_typing` (`Meta::send_typing`): while the composer has text after an edit (again every `TYPING_EVERY`), and a stop when it's emptied, Insert mode is left or the chat changes. There is no presence ("active now") at all: the helper must never send it (PROTOCOL.md, "What the helper must never do").
- Files go out only from `OpenChat.attachments`, listed by name and size in the composer, on Enter, and not if one was swapped since it was listed (`Attachment::swapped`). A paste attaches only absolute paths of existing files; `\\server\share` paths are never looked at (`attach::on_another_machine`). The clipboard is read only on `p` / Ctrl-v, and a paste that comes back after the chat changed (`Pasted.chat_id`) or once the keys went to the chat list is dropped.
- Login is by pasted cookies only (`LoginStep::Cookies`): the input is masked, the app checks the required names are there (`Network::cookie_names`) and hands the text to the helper, which keeps it only in its data folder. Passwords are never asked for. The login screen says tuimeta isn't Meta's and what that risks (`ui::NOT_META`).
- Media seen only once (Instagram's view-once, `Media.view_once`) has no file and no preview: the bubble names it and says to open it on the phone (`messages::ON_PHONE`). It's never downloaded or handed to another app.
- Encrypted Messenger chats (`Chat.encrypted`) show a 🔒 on `colors.secret` (`ui::lock_spans`), which a name starting with 🔒 can't imitate, and their composer's border says "end-to-end encrypted". Their notifications say only "Encrypted chat: New message".
- Service messages (`service.rs`) are the network's sentence, cleaned onto one line and drawn in the text color, never muted like a date, so a name can't pass for one.
- Images decode within `images::limits` (stickers within 1024 px), at most `MAX_BUILDING` at once, and a panic in a decoder only marks that image broken (`images::panic_is_contained`). Sixel and iTerm2 images aren't drawn under popups (`Images::paints_over`).
- Notification text goes through `notify::escape`. A panic restores the terminal and exits, printing the message through `text::clean`; the helper then sees its stdin close and stops without telling anyone anything.
- Settings are written 0600 through a rename (`Settings::save`); `clean_outbox` deletes only `pasted-<digits>.png/jpg`; `--demo` writes only into a new 0700 temp folder.

## Architecture

**Event loop (`app.rs`, `App::run`).** One `tokio::select!` over: the helper's events, finished image encodes, clipboard results, terminal key/paste/focus events, signals and the quit deadline. Each wake drains the event backlog, then redraws. All state lives in `App`; nothing else mutates it.

**Helper connection (`meta.rs`).** `Meta::start` spawns the helper, checks its `hello` line (protocol `PROTOCOL_VERSION`) and runs a reader and a writer task. Every request is fire-and-forget (`Meta::spawn`, or `Meta::then` to turn the answer into an event); answers and the helper's own events come back as `MetaEvent`s. Requests carry what was asked (chat id, `Page`, query) so stale answers can be dropped. The helper assigns every id: chat and user ids are unique across networks, message ids are chronological (`ms << 8 | slot`), so `OpenChat.messages` (a `BTreeMap`) stays in order, and a message with several photos arrives as consecutive "album" parts. `Meta::detached` (demo, tests) sends nothing and, in tests, records every request (`Meta::sent`) so tests can check what would have gone out. `MetaEvent::Gone` means the helper stopped: the status bar says so.

**Accounts and login.** `App.accounts` holds each network's `AccountState` from the helper's `account` events. `App::follow_accounts` shows the login screen while no account is ready, and the chats once one is. `LoginStep::Choose` picks a network, `LoginStep::Cookies` takes the paste; `:login` opens it over the chats (`Login.from_main`, so Esc goes back). `TM_BROWSER` ("Chrome 150.0.7712.45", read once into `App.browser`) goes with each login as `login_cookies`' `browser`: the helper (`internal/browser`) then says it's that Chrome on this computer's system instead of the libraries' Chrome 141 on Linux, saved with the session so a session never changes browser; only Chrome can be named, since the libraries' TLS handshake is Chrome's. A network logged out of (`:logout`, which asks and names it, or the session ending elsewhere) has its chats, jumps and highlights forgotten (`App::forget_network`).

**Chat list (`chats.rs`, `ui/chat_list.rs`).** Rebuilt from the helper's `chat` events (`Chats::upsert`, which keeps what only the app knows: who is typing, a downloaded photo). Order is unread first, then `order` (last activity in ms); a new message moves its chat at once (`Chats::on_message`). Tabs (`Chats::tabs`) are All, each network once there are two, and the archive once it has chats; Tab / Shift-Tab go round them. Chats load a page at a time per network, more as the cursor nears the end (`App::load_more_chats`), never all at once. `m` mutes on the network. Typing (`Chat.activity`) comes from `typing` events; the helper sends the stop itself.

**Open chat (`messages.rs`, `ui/messages.rs`).** As in tuigram: one unbroken stretch of history, `Page` (`Latest`/`Older`/`Newer`/`Around`) with `loading` the one request in flight, `selected: None` following the newest, `MAX_FOLLOWED`, `ScrollAnchor`. Messages are converted once (`Msg::from(&meta::Message)`): text with the media's label, links (the network's link entities and written-out addresses, `messages::links`), formatting (`styles`), the preview and file, the link card, the reply (`ReplyTo`, with the network's quote when it gives one, else fetched with `get_message`), reactions. A `message` event replaces a loaded message whole (`OpenChat::upsert`) or adds a new one at the newest. Sending shows the message pending at once (the helper's `message` event) and `message_sent` swaps it for the final id (`OpenChat::replace`). `e` edits only your text messages while `editable_until` allows; text with formatting asks first (`Confirmed::Edit`). `d` unsends your own message (`DeleteMenu`). Albums are drawn as one bubble (`ui::messages::albums`); their reactions and reply are on the first part, their text on the last.

**Reactions (`reactions.rs`).** One per person per message. `R` opens `ReactMenu` with `reactions::OFFERED` (Messenger's six and other common ones), your reaction first; `/` searches every emoji in the `emojis` crate, without joined ones. Enter makes the emoji yours, or takes it back if it is (`reactions::same` ignores U+FE0F); `X` takes yours back.

**Finding chats (`picker.rs`).** `s` lists your chats matching what's typed, then whom each ready network's `search` found once typing pauses (`SEARCH_AFTER`). Picking a person starts `open_dm`, answered by `MetaEvent::ChatFound` and kept only if it matches `App.finding` and nothing holds the keys.

**Notifications (`notify.rs`, `App::notify`).** Someone else's new message (`message.id` past the chat's `read_inbox` and the last one notified, `App.notified`), in a chat that isn't muted, from after the account came in (`notify_since`), that the user doesn't see (`App::sees`). `Notifier` batches them (`GAP`, `QUIET_CHAT`) and drops ones read elsewhere (`remove_read`) or deleted. The window title counts unread unmuted chats.

**The helper (`helper/`).** Go, pure (`CGO_ENABLED=0` builds for all six targets). `internal/server` reads requests and writes events (one writer, so lines never interleave), `internal/backend` is the `Backend` interface each network implements, with `Deps` (`internal/ids`: chat and person ids persisted in `ids.json`, message ids for the run, album splitting; `internal/session`; `internal/download`; the `Outbox` of messages being sent). `internal/fake` is the `--fake` world. `internal/messenger` drives mautrix-meta's messagix (facebook.com mode, cookie login, the session saved only after the first sync) and, for encrypted chats, whatsmeow as a registered device of the account, whose store and the encrypted messages it received (newest 3000 per chat; older encrypted history is only in Messenger's PIN-locked backup, which neither library can restore, so there's no PIN prompt) are in `messenger/e2ee.db` (modernc SQLite, 0600, not encrypted at rest yet). A task guard lets read receipts out only from `mark_read` and typing only from `typing`; the whatsmeow wrapper has no presence methods at all. Messenger's `logout` is local only: it disconnects and wipes what's stored (the encrypted-chat device store included) but never calls facebook.com's log-out, so the browser the cookies came from stays logged in. `internal/instagram` drives instameow (Instagram's protocol since July 2026; no encryption since May 2026): each file goes as its own message, a caption as a text after it, a shared post's link is added to the text so its card shows, and `logout` can't end the session on Instagram's side. `internal/metatext` turns both networks' inline markers (`*bold*` `_italic_` `~strike~` `` `code` ``) into entities. Every library logger writes nothing; `hlog` keeps only fixed words, numbers and error kinds. Downloads only go over https to Meta's CDN hosts. What each network still needs to send to work (socket pings, frame and delivery acks) is listed in `helper/README.md` → Privacy; keep that list true when changing a backend. The tests never touch a real account: they use hand-built library structs and recorded-looking JSON. The app has been tried live only on the author's own accounts (both networks log in, Messenger's encrypted chats connect); treat other live behavior as unproven.

**The rest** works as in tuigram: modes and keys (`on_key` routes to the first modal layer: confirm, photo viewer, settings, delete, react, open/copy menu, picker, resize, prompt, Insert, Normal; update the status bar hints and `ui/help.rs` `SHORTCUTS` when adding keys), `:` commands only by their full name with Tab completion (`login`, `logout`), images (`images.rs`), clipboard (`clipboard.rs`), attachments (`attach.rs`), themes (`theme.rs`), the demo (`demo.rs`: scenes `1`–`9`, never calls `App::run`).

## Conventions

- Rust 2024 edition; `let` chains are used freely.
- Comments explain why, in plain sentences; doc comments describe behavior as the user sees it.
- Test names are sentences. UI tests render into a `TestBackend` buffer and assert on rows/cells; app tests use `crate::demo::demo_app` with `Meta::detached` and check `Meta::sent`.
- The helper's Go code follows the same: plain comments on why, tests for everything, `--fake` kept complete enough to drive the whole UI.
